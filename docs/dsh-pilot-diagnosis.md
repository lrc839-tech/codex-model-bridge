## 三类疑似适配器错误的离线复现

已在全新的临时目录执行固定的本地模拟会话。复现脚本和完整诊断数据保存在未公开的控制区；此处仅发布脱敏结果。

1. **缺少 description**：真实官方 DSH 拒绝 bash 参数，命令确实没有执行；补齐参数后运行正常。
2. **file changed since it was read**：先由官方 read 观察文件，再通过 bash 修改文件，随后 native write 被拒绝。再次调用官方 read 后，同一个 native write 立即成功。
3. **file no longer exists**：通过 bash 删除一个已被 read 观察的文件后，native write 拒绝。再次 read 确认不存在后，native write 可以正常重建。

12 次本地模拟请求完成了上述过程和最终结束，8 项断言全部通过。三个 bash job 都以 0 退出。这说明这里的 stale/missing 错误符合官方 DSH 文件观察与并发保护机制；正式轨迹中，模型多次通过 shell 修改/删除后没有先刷新 native read 观察。没有依据去放松该保护或改写工具输出让运行看起来成功。

## 用量为什么变成 unknown

最后一个 API 请求已经开始，360 秒总超时终止 worker 时还没有完成 usage 回执，因此账本只有 163 个 start 和 162 个 finish。未完成请求可能已经产生费用，必须保留 unknown 并停止后续提交，不能补记为 0。

这与“工具 broker 142 个 job 都已经结束”并不矛盾：结束的是此前的本地命令，尚未完成的是下一次模型 HTTP 请求。
